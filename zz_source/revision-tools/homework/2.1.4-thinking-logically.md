## Mark scheme

**Part A (14 marks)**

**1. [3]** — 1 mark per gap:

- (a) `score >= 70` — must use `>=`; "70 or above" includes exactly 70, so `>` earns nothing.
- (b) `score >= 40`
- (c) `else`

The order matters: 70+ is tested first, so the `elseif` is only reached when the score is below 70.

**2. [2]** — Two correct rows per mark:

| Requirement | Boolean condition |
|-------------|-------------------|
| At least 1.4 m | `height >= 1.4` (accept `height >= 140` if cm stated) |
| More than 500 | `score > 500` |
| No more than the balance | `amount <= balance` |
| Falls below 18 | `temp < 18` |

The operator must match the wording exactly ("at least" → `>=`, "more than" → strict `>`, "no more than" → `<=`, "falls below" → strict `<`).

**3. [4]** — 1 mark per row; for a false row the mark needs **False** plus a valid correction.

| Statement | True / False | Correction |
|-----------|--------------|------------|
| `spent > 100` awards the discount at exactly £100 | **False** | 100 is not greater than 100, so exactly £100 does **not** qualify; the condition should be `spent >= 100`. |
| `OR` allows a withdrawal only when both limits are satisfied | **False** | `OR` is true when **either** limit alone is satisfied; the condition must use **AND**: `amount <= balance AND amount <= dailyLimit`. |
| `elseif` tested only when the first condition is false | **True** | — |
| Pump left unchanged at exactly 50% | **True** | — (neither `level < 20` nor `level > 80` is true, so neither branch runs) |
