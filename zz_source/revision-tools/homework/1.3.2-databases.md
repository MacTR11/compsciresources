**3. [3]** Sample answer:
```sql
SELECT Member.Surname, Booking.CourtNumber, Booking.BookingDate
FROM Member
JOIN Booking ON Member.MemberID = Booking.MemberID;
```
1 mark: SELECT lists Surname, CourtNumber and BookingDate; 1 mark: FROM/JOIN names both tables; 1 mark: correct join condition `ON Member.MemberID = Booking.MemberID`. (Accept table aliases, `INNER JOIN`, or an equivalent implicit join in a WHERE clause.)

(a) [2]** A single order record would contain a repeating group — several `ProductID`/`ProductName`/`Quantity` values in one row — so values are not atomic (1). 1NF requires no repeating groups / every attribute to hold a single (atomic) value, with a primary key defined (1). **5. [2]** Durability: once a transaction has been committed, its changes are permanent — they are written to non-volatile storage (e.g. via a transaction log) (1). So if the server loses power after the commit, the payment is not lost — the committed change survives the failure/restart (1).
