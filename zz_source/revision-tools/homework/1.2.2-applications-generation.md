**3. [3]** — 1 mark per row:

- (a) Lexical analysis: the source code is converted into a series of **tokens**; whitespace and comments are removed; a **symbol table** of identifiers (variables, subroutines) is created for later stages to look up.
- (b) Syntax analysis: the tokens are checked against the **grammar rules** of the language (e.g. by building an abstract syntax tree); errors are reported if the rules are broken.
- (c) Optimisation: the code is refined/rearranged so it runs **faster and/or uses less memory** while producing exactly the same result.

**4. [3]** — 1 mark per statement correctly fixed:

- 1: The **linker** combines the compiled modules and library code into a single executable. *(The loader's job is to copy the finished executable from secondary storage into RAM and prepare it to run.)*
- 2: That describes **dynamic** linking. With **static** linking, the library code is **copied into the executable at compile/link time**, so updating the library does not update already-built programs.
- 3: That is an advantage of **static** linking. A **dynamically** linked program depends on the separate library file (e.g. a .dll) being present at run time.

**5. [3]** — Open source advantages (1 each, max 2): free / no licence cost; source code can be viewed and modified to suit the school; large community support; not tied to one vendor. Closed source advantage (1): official/dedicated vendor support and warranties; often more polished / fully tested / regular professional updates. Max 3.
